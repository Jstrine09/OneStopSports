1. Project Overview

OneStopSports is a full-stack sports scores app inspired by Fotmob. It supports three sports (Futbol/Soccer, Basketball/NBA, and American Football/NFL) and provides:

  • Live scores pushed via WebSocket in real time
  • League standings with colour-coded promotion/relegation zones
  • Team rosters grouped by position
  • Match timelines (goals, cards, substitutions — football only)
  • User accounts with saved favourite teams and players

The backend is a stateless Spring Boot REST API protected by JWT. The frontend is a React SPA that connects via REST (React Query) and WebSocket (STOMP over SockJS) for live data.

Request Flow (example: GET /api/leagues/7/standings)

  1. JwtAuthFilter — checks for a Bearer token. If valid, sets user in SecurityContextHolder. If absent, passes through (public endpoint).
  2. SecurityConfig — the request matches GET /api/** → permitAll(), so no auth required.
  3. LeagueController.getStandings() — delegates to LeagueService.getStandings(7).
  4. LeagueService — loads league from DB, reads league.getSport().getSlug(). Routes: "basketball" → NbaApiService, "american-football" → NflApiService, default → ExternalApiService.
  5. The API response is mapped to a list of StandingsEntryDto records and returned as JSON.

4. Security — JWT + Spring Security 6

How JWT Authentication Works

  1. User calls POST /api/auth/login with username + password.
  2. AuthService.login() calls authenticationManager.authenticate() — Spring checks the password against the stored hash via UserDetailsService.loadUserByUsername().
  3. On success, JwtUtil.generateToken(username) creates a signed JWT with a 24-hour expiry.
  4. Token is returned to the client, which stores it in localStorage.
  5. Every subsequent request includes Authorization: Bearer <token>.
  6. JwtAuthFilter (runs before all controllers) extracts and validates the token, then sets the user in SecurityContextHolder.
  7. Controllers can then call principal.getName() to get the username.

Spring Security 6 Config Pattern

@Bean
public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    http
        .csrf(csrf -> csrf.disable())         // Stateless API — no CSRF needed
        .sessionManagement(session ->
            session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
        .authorizeHttpRequests(auth -> auth
            .requestMatchers(HttpMethod.GET, "/api/**").permitAll()
            .requestMatchers("/api/auth/**").permitAll()
            .requestMatchers("/swagger-ui/**", "/v3/api-docs/**").permitAll()
            .requestMatchers("/api/users/me/**").authenticated()
            .anyRequest().authenticated())
        .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class);

}

Circular Dependency Fix

The cycle was: JwtAuthFilter → AuthService → PasswordEncoder (in SecurityConfig) → JwtAuthFilter. Fixed two ways:

  1. PasswordEncoder moved to its own PasswordConfig.java — breaks the SecurityConfig dependency.
  2. AuthenticationManager in AuthService is injected with @Lazy — Spring doesn't try to create it until the first login() call.

5. External APIs — Football, NBA, NFL

Football — football-data.org v4

  • Base URL: https://api.football-data.org/v4
  • Auth: X-Auth-Token: <key> header
  • Rate limit: 10 requests/min on free tier → DataLoader sleeps 6.2s between competition fetches
  • 6 leagues seeded: Premier League, La Liga, Bundesliga, Serie A, Ligue 1, Champions League
  • Match times returned as UTC ISO-8601 — stored and displayed as UTC (football fans worldwide, no single timezone)
  • Key response records (all nested inside ExternalApiService.java):
ApiTeamsResponse(competition, teams[])
ApiMatch(id, homeTeam, awayTeam, score, status, utcDate, competition)
ApiMatchDetail(…, goals[], bookings[], substitutions[])  ← GET /matches/{id}
ApiStandingsResponse(competition, standings[{type, table[]}])

NBA — ESPN Unofficial API (no API key needed)

  • Base URL: https://site.api.espn.com/apis/site/v2/sports/basketball/nba
  • Standings URL: https://site.web.api.espn.com/apis/v2/sports/basketball/nba/standings (different subdomain — separate RestClient)
  • No API key required — public/unofficial endpoint
  • Date format for scoreboard: YYYYMMDD (no dashes), e.g. 20250209
  • Roster: athletes is a flat array — simpler than NFL's grouped-by-side structure
  • Positions are full names ("Center", "Guard", "Forward") — no mapping needed
  • Teams have crestUrl from ESPN CDN: https://a.espncdn.com/i/teamlogos/nba/500/bos.png
  • dateOfBirth available from ESPN — NBA players have DOB
  • Season year logic: month >= 10 ? year + 1 : year (Oct 2024 = "2024-25" season)
  • Status mapping: STATUS_FINAL→FINISHED, STATUS_IN_PROGRESS→LIVE, else→SCHEDULED
  • Key inner records (nested inside NbaApiService.java):
EspnTeamsResponse, EspnSport, EspnLeague, EspnTeamEntry, EspnTeam, EspnLogo
EspnRosterResponse, EspnAthlete, EspnAthletePosition, EspnBirthPlace
EspnScoreboardResponse, EspnEvent, EspnEventStatus, EspnStatusType,
EspnCompetition, EspnCompetitor, EspnCompTeam
EspnStandingsResponse, EspnConference, EspnStandingsSection,
EspnStandingsEntry, EspnStandingsTeam, EspnStat

NFL — ESPN Unofficial API (no API key needed)

  • Base URL: https://site.api.espn.com/apis/site/v2/sports/football/nfl
  • Same ESPN pattern as NBA, but different sport path and data structure differences
  • Date format for scoreboard: same YYYYMMDD format

6. Multi-Sport Routing & ET Timezone Display

Sport Routing

The DB schema is sport-agnostic: sport → league → team → player. Routing to the correct API happens by reading the league's sport slug:

@Transactional(readOnly = true) // Opens a Hibernate session so league.getSport() (LAZY) can load
public List<MatchDto> getMatchesByLeagueAndDate(Long leagueId, LocalDate date) {
    return leagueRepository.findById(leagueId).map(league -> {
        String sportSlug = league.getSport().getSlug();
        return switch (sportSlug) {
            case "basketball"        -> nbaApiService.fetchGameDtosByDate(date, league.getId());
            case "american-football" -> nflApiService.fetchGameDtosByDate(date, league.getId());
            default -> league.getExternalId() != null
                ? externalApiService.fetchMatchDtosByCompetition(league.getExternalId(), date)
                : Collections.emptyList();
        };
    }).orElse(Collections.emptyList());
}

The same "basketball" / "american-football" / default routing pattern applies in LeagueService.getStandings().

Why @Transactional(readOnly = true)? All @ManyToOne relationships use FetchType.LAZY — Hibernate doesn't load the related object until you access it. Without an open Hibernate session, accessing league.getSport() would throw a LazyInitializationException. @Transactional keeps the session alive for the duration of this method call.

getMatchById() and getMatchEvents() are football-only — they always delegate to ExternalApiService. NBA and NFL do not expose per-match event APIs at the free/public tier.

ET Timezone Display (NBA + NFL)

Problem: ESPN returns game times as UTC ISO-8601 strings (e.g. "2025-04-26T23:30Z"). The backend was stripping the offset with .toLocalDateTime(), producing a naive LocalDateTime. A browser in Ireland (BST = UTC+1) would show "11:30 PM" for a "7:30 PM ET" game.

Fix: Convert UTC → Eastern Time in NbaApiService and NflApiService before building the MatchDto:

startTime = OffsetDateTime.parse(event.date())
        .atZoneSameInstant(ZoneId.of("America/New_York"))
        .toLocalDateTime();

ZoneId.of("America/New_York") handles EDT/EST transitions automatically. A 7:30 PM ET April game (23:30 UTC) becomes LocalDateTime("19:30:00"). The frontend receives "19:30:00" — any browser displays "7:30 PM" regardless of locale.

MatchDto.timezone field: The 9th field in the record is String timezone. Value is "ET" for NBA/NFL and null for football. Football times are left as UTC and displayed without a label — football is a global sport and users worldwide are used to seeing UTC times.

// Frontend: MatchCard.tsx + MatchDetailPage.tsx
function formatKickoff(utc: string, timezone?: string | null): string {
  const time = new Date(utc).toLocaleTimeString([], { hour: '2-digit', minute: '2-digit' })
  return timezone ? `${time} ${timezone}` : time  // → "7:30 PM ET" or "19:30"
}

7. WebSocket Live Push

Architecture

The app uses STOMP (Simple Text Oriented Messaging Protocol) running over WebSocket, with SockJS as a fallback transport for browsers that don't support native WebSocket.

Server Side (Backend)

  1. WebSocketConfig sets up the STOMP broker at /topic and registers /ws as the SockJS endpoint.
  2. MatchService.refreshLiveMatchCache() runs every 30 seconds via @Scheduled(fixedDelay = 30_000).
  3. It fetches live football matches via ExternalApiService.fetchLiveMatchDtos(), NBA live games via leagueRepository.findBySport_Slug("basketball"), and NFL live games via findBySport_Slug("american-football").
  4. Builds a snapshot: matchId → "homeScore:awayScore:status".
  5. If the snapshot differs from the previous tick, it:
    • Updates the Redis cache directly (cache.put(SimpleKey.EMPTY, current)) so REST calls return fresh data
    • Broadcasts via messagingTemplate.convertAndSend("/topic/matches/live", current)
// Only push when something actually changed — no flooding on quiet ticks
if (!snapshot.equals(previousSnapshot)) {
    previousSnapshot = snapshot;
    Cache cache = cacheManager.getCache("matches");
    if (cache != null) cache.put(SimpleKey.EMPTY, current); // Update Redis
    messagingTemplate.convertAndSend("/topic/matches/live", current); // WebSocket push
}

Client Side (Frontend)

// useLiveScores.ts — custom React hook
const client = new Client({
    webSocketFactory: () => new SockJS('/ws'),  // /ws proxied by Vite to localhost:8080
    reconnectDelay: 5_000,
    onConnect: () => {
        client.subscribe('/topic/matches/live', (message) => {
            const matches = JSON.parse(message.body)
            onUpdate(matches)  // caller: queryClient.setQueryData(['matches','live'], matches)
        })
    }
})
client.activate()
Why SimpleKey.EMPTY? When a @Cacheable method has no arguments, Spring's SimpleKeyGenerator uses SimpleKey.EMPTY as the cache key. To manually write into that same cache slot, you pass SimpleKey.EMPTY as the key to cache.put().
Redis / Jackson gotcha: The default GenericJackson2JsonRedisSerializer uses a bare ObjectMapper that cannot handle LocalDateTime. The custom RedisConfig uses an ObjectMapper with JavaTimeModule + DefaultTyping.EVERYTHING to fix this. The same root cause affects WebSocketConfig — it overrides configureMessageConverters to inject Spring Boot's auto-configured ObjectMapper instead of the default bare one.

8. Database Seeding

Football (DataLoader)

  • Runs at startup via CommandLineRunner
  • Skip condition: leagueRepository.count() >= 6 (number of competitions)
  • Seeds: 1 Sport (Futbol, slug=football) → 6 Leagues → up to 20 Teams each → full squads (~1000+ players)
  • Sleeps 6.2s between competitions to respect the 10 req/min rate limit
  • Sport is called "Futbol" (not "Football") to distinguish from NFL — slug stays football so URLs are unchanged

NBA (NbaDataLoader)

  • Independent from DataLoader — runs separately at startup
  • Skip condition: all 30 teams exist AND at least one has a crestUrl (ESPN-sourced) — if crestUrls are all null (old data), re-runs to update logos
  • Seeds: 1 Sport (Basketball, slug=basketball) → 1 League (NBA) → 30 Teams (with ESPN logo URLs) → full rosters
  • Teams have crestUrl from ESPN CDN (e.g. https://a.espncdn.com/i/teamlogos/nba/500/bos.png)
  • Players have dateOfBirth from ESPN (ISO-8601 parsed to LocalDate)
  • No API key required — ESPN is a public/unofficial endpoint

NFL (NflDataLoader)

  • Independent from the other loaders — runs separately at startup
  • Skip condition: teamRepository.findByLeagueId(nfl.getId()).size() >= 32 — if all 32 teams exist, skip entirely; partial seeding fills in missing teams only
  • Seeds: 1 Sport (American Football, slug=american-football) → 1 League (NFL) → 32 Teams (ESPN logo URLs) → rosters (~53 active players each)
  • Sleeps 1500ms between roster fetches to avoid rate-limiting
  • Season label: "2025-26"
  • Players do not have dateOfBirth — ESPN NFL endpoint doesn't return it
  • Position abbreviations ("QB", "WR", "CB") stored as-is
All three loaders are idempotent: each checks whether data already exists before fetching from the API, so restarting the app never re-seeds. The NBA loader has an extra check that repairs teams with missing crestUrls from an old data source.

9. Error Handling — GlobalExceptionHandler

GlobalExceptionHandler is annotated with @RestControllerAdvice — it intercepts any exception thrown from a controller and returns a consistent JSON error response instead of Spring's default HTML error page.

// ErrorResponseDto — every error returns this JSON shape
{ "status": 400, "error": "Bad Request", "message": "username must not be blank", "timestamp": "…" }
ExceptionHTTP StatusTrigger
MethodArgumentNotValidException400@Valid fails on a request body
HttpMessageNotReadableException400Malformed JSON in request body
ResponseStatusExceptionpassthroughManually thrown (e.g. 404 Not Found)
BadCredentialsException401Wrong password on login
AccessDeniedException403Authenticated but not authorised
DataIntegrityViolationException409Duplicate key in DB (e.g. duplicate favourite)
Exception (catch-all)500Anything unexpected
Critical ordering rule: ResponseStatusException MUST have its own @ExceptionHandler BEFORE the generic Exception catch-all. Without it, the catch-all intercepts ResponseStatusException and returns 500 instead of the intended status code (e.g. 404).

11. Redis Cache

  • MatchService.getLiveMatches() is annotated with @Cacheable("matches") — the first call fetches from the API, subsequent calls within 30s return the cached result
  • Cache TTL is 30 seconds, configured in RedisConfig via RedisCacheConfiguration.entryTtl(Duration.ofSeconds(30))
  • Values are serialised as JSON with type info using GenericJackson2JsonRedisSerializer — this allows correct deserialisation back to List<MatchDto>
  • The WebSocket scheduler (refreshLiveMatchCache) manually updates the cache with cache.put(SimpleKey.EMPTY, current) so REST calls stay in sync with WebSocket pushes
  • Custom ObjectMapper with JavaTimeModule + DefaultTyping.EVERYTHING is required because the default serialiser uses a bare ObjectMapper that can't handle LocalDateTime

12. Testing Strategy

The project has 48 tests total, all pure unit tests or web-layer slice tests — no integration tests requiring a running database or Redis.

AuthServiceTest — 6 Pure Unit Tests

Uses @ExtendWith(MockitoExtension.class) — no Spring context, no database. Mockito creates fake versions of all dependencies (UserRepository, PasswordEncoder, JwtUtil, AuthenticationManager).

Covers: successful register, duplicate username (409), duplicate email (409), successful login, wrong password, loadUserByUsername.

AuthControllerTest — 7 @WebMvcTest Slice Tests

Uses @WebMvcTest — loads only the web layer (controllers, filters, security). No database, no services.

Key gotcha: @WebMvcTest does NOT auto-scan @Configuration classes. SecurityConfig is a @Configuration class and is silently excluded. Without it, Spring Security falls back to its default "deny all" rule and every request returns 401 — even public endpoints like /api/auth/register. Fix: Add @Import(SecurityConfig.class) to the test class.
@WebMvcTest(
    value = AuthController.class,
    excludeAutoConfiguration = UserDetailsServiceAutoConfiguration.class
    // ↑ Without this, Spring auto-creates an InMemoryUserDetailsManager AND our mocked
    //   AuthService both implement UserDetailsService → "expected single matching bean but found 2"
)
@Import(SecurityConfig.class) // ← Brings in our custom SecurityFilterChain with permitAll() rules
class AuthControllerTest { … }

All POST requests need .with(csrf()) from spring-security-test (separate Maven dependency).

MatchServiceTest — 13 Pure Unit Tests

Uses @ExtendWith(MockitoExtension.class). All five dependencies (ExternalApiService, NbaApiService, NflApiService, LeagueRepository, SimpMessagingTemplate, CacheManager) are mocked.

Covers: null leagueId/date guard clauses, unknown league (empty Optional), basketball routing to NbaApiService, american-football routing to NflApiService, football with/without externalId, getMatchById (null + valid), getMatchEvents (null + valid), getMatchStats/getMatchLineups return empty maps.

Key gotcha — primitive int parameters: fetchMatchDtosByCompetition(int, LocalDate) takes a primitive int. Mockito's any() returns null — auto-unboxing null to int causes an NPE. Always use anyInt() for primitive int parameters in verify()/when() calls.

NbaApiServiceTest — 12 Pure Unit Tests

Tests the NBA API mapping logic without making real HTTP calls.

// RETURNS_DEEP_STUBS makes every method in a fluent chain return a sub-mock,
// so restClient.get().uri(...).retrieve().body(Class) can be stubbed without
// every intermediate call needing to match.
@Mock(answer = Answers.RETURNS_DEEP_STUBS)
RestClient restClient;

@BeforeEach
void setUp() {
    // Package-private test constructor — injects mock RestClients directly,
    // bypassing the @Value URL parameter.
    nbaApiService = new NbaApiService(restClient, standingsClient);
}
Why a package-private test constructor? The production constructor takes a @Value("${...}") String baseUrl and builds the RestClient internally. Tests can't inject a mock that way. The package-private constructor skips the @Value and accepts pre-built RestClient instances directly. Adding @Autowired to the production constructor tells Spring which one to use (required when there are two constructors).

Covers: null scoreboard response, STATUS_FINAL→FINISHED, STATUS_IN_PROGRESS→LIVE, scheduled games show null scores, leagueId propagation, standings sorted by wins descending, API exception→empty list, draws always 0 (NBA has no draws), played = wins + losses.

LeagueServiceTest — 9 Pure Unit Tests

Covers: getStandings 404 on unknown league, basketball/american-football/football routing, football without externalId returns empty list, getLeagueById found/not found, getLeaguesBySport.

OneStopSportsApplicationTests — 1 Context Load Test

RedisConfig creates a RedisCacheManager that needs a real RedisConnectionFactory. Fix: add @MockBean RedisConnectionFactory redisConnectionFactory to the test class.

  2. Token stored in localStorage.

  homeScore: number | null

  status: string        // SCHEDULED | TIMED | IN_PLAY | LIVE | PAUSED | FINISHED | HALFTIME | …
  startTime: string | null  // NBA/NFL: already converted to ET. Football: UTC.
  leagueId: number | null
  timezone: string | null   // "ET" for NBA/NFL — shown as a label next to the time. null for football.
}

17. Local Dev Setup

Prerequisites

Java 21+, Maven 3.9+, Node 20+, Docker Desktop, API key from football-data.org (free)

Option A — Maven (fastest for active development)

Postgres + Redis via Docker, app runs on the host via Maven.

# 1. Start infra only
docker-compose up -d postgres redis

# 2. Add secrets to application-local.yml (gitignored)
cp .env.example src/main/resources/application-local.yml
# edit: add football-data api-key and jwt.secret

# 3. Run backend
mvn spring-boot:run -Dspring-boot.run.profiles=local
# First boot seeds all three sports (~5 min total: football ~3 min, NBA ~1 min, NFL ~1.5 min)

# 4. Run frontend
cd frontend && npm install && npm run dev
# App available at http://localhost:5173

# 1. Create .env from example
cp .env.example .env
# edit: set FOOTBALL_DATA_API_KEY and JWT_SECRET

# 2. Build and start everything
docker-compose up --build
# App ready at http://localhost:8080 once "Started OneStopSportsApplication" appears

Run tests (no Postgres/Redis needed)

mvn test   # 48 tests — all unit/slice tests, no external services required
